# API Contracts: Disruption & Flight-Change Management

All responses use existing global error formatting and correlation/trace propagation. Traveller endpoints require JWT authentication and booking ownership. Admin endpoints require JWT plus `ADMIN`. Raw Duffel payload, passenger PII, contact details, and payment data are never returned.

## Public supplier endpoint

### POST `/api/duffel/webhook`

Authentication: Duffel HMAC signature, not JWT.

Headers:

- `X-Duffel-Signature` — required `t=...,v1=...` signature over raw request bytes.
- Existing trace/correlation header is accepted or generated by the platform.

Supported initial event: `order.airline_initiated_change_detected`.

Behavior:

1. Validate header format, replay tolerance, signature, and minimal event envelope.
2. Insert a small durable inbox record using Duffel event ID as unique identity.
3. Return without fetching Duffel or running the synchronization pipeline.
4. A verified duplicate returns the same successful acknowledgement.
5. A verified unsupported event is recorded as `SKIPPED` and acknowledged.

Success `200`:

```json
{ "received": true }
```
Errors:

- `400 WEBHOOK_SIGNATURE_MISSING` — missing header; no row.
- `400 WEBHOOK_SIGNATURE_INVALID` — malformed/invalid/stale signature; no row.
- `400 WEBHOOK_PAYLOAD_INVALID` — verified body lacks required event envelope; no processable row.
- `503 WEBHOOK_INBOX_UNAVAILABLE` — durable insert could not be confirmed; Duffel should retry.

Performance contract: durable acknowledgement p95 below 500 ms and zero supplier calls in the request.

## Existing booking detail extension

### GET `/api/bookings/:bookingId`

The existing owner-scoped booking detail response gains:

```json
{
  "currentItinerary": {
    "source": "ORIGINAL|REVISION",
    "revisionId": "uuid-or-null",
    "version": 3,
    "segments": [],
    "nextUnflownDepartureAt": "2026-07-25T08:00:00Z",
    "finalArrivalAt": "2026-08-02T17:20:00Z"
  },
  "disruption": {
    "status": "NONE|DETECTED|ACKNOWLEDGED|RESOLVED",
    "activeRevisionId": "uuid-or-null",
    "isMaterial": true,
    "materialReasons": ["DEPARTURE_MOVED_EARLIER"],
    "incrementalSummary": {},
    "cumulativeSummary": {},
    "stabilizationWarning": false,
    "resolvedReason": null,
    "resolvedAt": null
  }
}
```

Rules:

- `flightSnapshot` retains original booking-time semantics.
- `currentItinerary` uses the latest revision when present, otherwise the original snapshot.
- The endpoint performs no Duffel call and is served uncached by the protected web page.
- Other-owner booking remains `403`; missing booking remains `404`, matching the existing contract.

## Traveller disruption history

### GET `/api/bookings/:bookingId/disruptions?page=1&limit=20`

Query:

- `page`: integer >=1, default 1.
- `limit`: integer 1–50, default 20.

Success `200`:

```json
{
  "items": [
    {
      "revisionId": "uuid",
      "version": 3,
      "observedAt": "2026-07-24T10:30:00Z",
      "isMaterial": true,
      "materialReasons": ["SEGMENT_REMOVED", "SEGMENT_ADDED"],
      "materialBaselines": ["INCREMENTAL", "CUMULATIVE"],
      "incrementalSummary": {},
      "cumulativeSummary": {},
      "segments": []
    }
  ],
  "page": 1,
  "limit": 20,
  "total": 3,
  "totalPages": 1
}
```

Newest version first. Diff summaries expose only safe presentation data and match confidence; no raw inbox payload.

Errors: `403` other owner, `404` booking missing.

## Traveller lifecycle commands

### POST `/api/bookings/:bookingId/disruptions/:revisionId/acknowledge`

Body: empty.

Preconditions:

- caller owns booking;
- `revisionId` is the booking’s active revision;
- active state is `DETECTED`, or is already `ACKNOWLEDGED` by an earlier identical command.

Success `200`:

```json
{
  "bookingId": "uuid",
  "activeRevisionId": "uuid",
  "disruptionStatus": "ACKNOWLEDGED",
  "resolvedReason": null,
  "updatedAt": "2026-07-24T10:35:00Z"
}
```

Same-revision replay returns canonical success. A resolved same revision returns its canonical state without reopening it.

### POST `/api/bookings/:bookingId/disruptions/:revisionId/accept`

Body: empty.

Preconditions: same active-revision ownership rule; state may be `DETECTED`, `ACKNOWLEDGED`, or already resolved as `TRAVELLER_ACCEPTED` by an identical command.

Success `200`:

```json
{
  "bookingId": "uuid",
  "activeRevisionId": "uuid",
  "disruptionStatus": "RESOLVED",
  "resolvedReason": "TRAVELLER_ACCEPTED",
  "resolvedAt": "2026-07-24T10:36:00Z",
  "updatedAt": "2026-07-24T10:36:00Z"
}
```

This command is local-only and performs no Duffel request.

Lifecycle command errors:

- `403` caller does not own booking.
- `404` booking or revision does not exist under the booking.
- `409 STALE_DISRUPTION_REVISION` when the path revision is no longer active. Response includes a safe canonical summary:

  ```json
  {
    "code": "STALE_DISRUPTION_REVISION",
    "activeRevisionId": "new-uuid",
    "disruptionStatus": "DETECTED"
  }
  ```

- `409 DISRUPTION_TRANSITION_INVALID` for a non-idempotent invalid transition.

Every successful state change writes an immutable audit event with actor, revision, prior/new state, trace, and correlation IDs.

## Existing cancellation command integration

### POST `/api/bookings/:bookingId/cancel`

The request/response remains unchanged. When supplier cancellation is conditionally finalized to `CANCELLED_PENDING_REFUND`, the same database write also:

- sets disruption status to `RESOLVED` when an active unresolved disruption exists;
- sets reason `BOOKING_CANCELLED`, time, and actor metadata;
- writes a disruption audit event.

Stripe refund success/failure does not reopen the disruption. Disruption status does not change cancellation eligibility, deadline, or refund amount.

## Admin disruption queue

### GET `/api/admin/disruptions`

Query:

- `status`: optional `DETECTED|ACKNOWLEDGED|RESOLVED`.
- `attention`: optional `true|false`.
- `attentionReason`: optional enum.
- `olderThanMinutes`: optional positive integer for aged active disruptions.
- `page`, `limit` (max 100).

Returns SQL-paginated PII-safe rows with booking ID, order correlation, active revision/version/reasons, state age, attention reason/time, last synchronization time, and safe audit summary. It does not return passenger/contact/payment data.

### POST `/api/admin/disruptions/:bookingId/resolve`

Body:

```json
{
  "revisionId": "uuid",
  "note": "Validated with airline operations; traveller contacted."
}
```

`note` is required, trimmed, sanitized, and length-limited. The active revision precondition applies. Success returns `RESOLVED`, `ADMIN_RESOLVED`, actor ID, and timestamps. Stale revision returns `409` with canonical active state.

### POST `/api/admin/disruptions/:bookingId/clear-attention`

Body:

```json
{ "note": "Schedule stabilized and case reviewed." }
```

Clears only operations-attention metadata and writes an audit event; it does not alter traveller disruption status.

## Admin inbox operations

### GET `/api/admin/duffel-events`

Query: `status`, `eventType`, `orderId`, `page`, `limit` (max 100).

Returns supplier event ID, order ID, safe status/attempt/error code, next attempt, lease age, and timestamps. It never returns `rawPayload`.

### POST `/api/admin/duffel-events/:eventId/retry`

Body:

```json
{ "note": "Supplier access restored; retry approved." }
```

Only `FAILED_NEEDS_ATTENTION` may be reset to `PENDING`. Retry clears lease/error scheduling fields, preserves attempt/audit history, and writes an admin audit event. Duplicate admin commands converge on canonical state.

## Admin data-quality report

### GET `/api/admin/disruptions/data-quality`

Returns paginated PII-safe counts/items for confirmed bookings missing/duplicating Duffel order ID, missing/invalid original snapshots, or lacking derivable next/final times. No supplier call is made.

## Internal application contracts

### Supplier synchronization command

```text
syncBooking(
  bookingId,
  source: WEBHOOK | RECONCILIATION | BOOTSTRAP,
  correlation: { eventId?, traceId, correlationId },
  policy: { createOutbox: boolean, surfaceToCustomer: boolean }
) ->
  NO_CHANGE | REVISION_CREATED | SKIPPED_INELIGIBLE | CONVERGED_DUPLICATE
```

The command owns all authoritative fetch, fingerprint, diff, classification, short transaction, and lock-release semantics.

### Reconciliation handler

The scheduled decorator calls a public handler that can be invoked directly in tests. It returns counts only:

```json
{
  "selected": 20,
  "processed": 18,
  "unchanged": 14,
  "changed": 4,
  "failed": 2,
  "budgetDeferred": 0
}
```
